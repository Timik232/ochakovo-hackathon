# API: контракты и соглашения

Источник истины — код backend (Pydantic-схемы, FastAPI). Экспорт:
`cd backend && uv run python -m scripts.export_openapi` → `backend/openapi.json`.
Фронтенд-типы: `cd frontend && npm run api:generate` → `src/api/schema.d.ts`
(хранится в репозитории; `npm run api:check` завершается ненулевым кодом при
дрейфе). Изменение контракта без обновления docs/типов/тестов запрещено.

## Префиксы и версионирование

- Доменные ресурсы: `/api/v1/...`. Версия — часть пути; `operationId` стабильны
  и не переименовываются.
- Health (вне версионирования): `/api/health/live`, `/api/health/ready`.

## Формат ошибок (единый конверт)

Любая ошибка возвращает JSON-объект:

```json
{
  "code": "MACHINE_READABLE_CODE",
  "message": "Человекочитаемое описание на русском",
  "field_errors": { "field": "текст ошибки поля" },
  "request_id": "uuid-запроса"
}
```

- `code` — стабильный машиночитаемый код (например `ACCOUNT_PENDING`,
  `VERSION_CONFLICT`, `PRIVACY_REVISION_CHANGED`).
- `field_errors` и `request_id` — необязательные поля (присутствие обозначено `?`).
- HTTP-коды: 401 не аутентифицирован, 403 нет прав/запрещённое состояние,
  404 не существует, 409 конфликт (версия/идемпотентность/дубликаты),
  422 ошибка валидации, 429 превышен лимит запросов, 503 приём отключён/сервис
  деградировал.

## Пагинация (единый конверт списков)

```json
{
  "items": [ ... ],
  "total": 123,
  "page": 1,
  "page_size": 20
}
```

Параметры: `page >= 1`; `page_size` из допустимого набора (по умолчанию 20,
максимум 100); сортировка — по whitelist полей; ответ всегда содержит `total`.

## Семантика версий optimistic concurrency

- `PATCH /api/v1/candidates/{id}` принимает `version` в теле; сервер выполняет
  `UPDATE ... WHERE id AND version` с инкрементом; устаревшая версия →
  409 `VERSION_CONFLICT`.
- `DELETE /api/v1/candidates/{id}` требует заголовок `If-Match: "<integer>"`:
  отсутствие/некорректность → 422, устаревание → 409, отсутствие записи → 404.

## Health-эндпоинты (реализованы в T1)

- `GET /api/health/live` → всегда `200 {"status": "ok"}`; БД не проверяется.
- `GET /api/health/ready` → `200 {"status": "ok", "database": "up"}`, если БД
  отвечает и `alembic_version` равна единственной голове миграций (определяется
  из каталога миграций на старте, не хардкодом). Иначе — санитизированный
  503-конверт `{"code": "DB_UNAVAILABLE" | "SCHEMA_MISMATCH", "message",
  "request_id"}` без деталей SQL и без падения процесса.

## Идемпотентность публичной анкеты (контракт T5)

`POST /api/v1/public/applications` принимает ключ идемпотентности; повтор
того же ключа с тем же каноническим телом возвращает ту же квитанцию, с другим
телом — 409.

## Правила для всех эндпоинтов

- Тела запросов/ответов — JSON; кодировка UTF-8; подписи на русском.
- `Cache-Control: private, no-store` на API-ответах.
- Заголовок `X-CSRF-Token` обязателен на аутентифицированные мутации (с T3);
  для login/register/public submit — проверка exact `Origin`.
- Реальные персональные данные не попадают в URL, кроме документированного
  исключения `q` поиска (см. план, раздел List/API/UX).
